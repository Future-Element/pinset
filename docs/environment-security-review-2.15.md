# Environment state and candidate execution review

Scope: local directory ownership, inherited encrypted profiles, snapshot inputs, subprocess lifetime, candidate application and restoration for the combined 2.15 release. This review records the implementation boundaries required by CONTRIBUTING; it is not a claim of an external penetration test.

- Local trust, selection, venv and editor state require matching canonical directory, filesystem generation and host. OS identity takes priority over shell-only hostname exports; macOS uses its host UUID and Windows reads MachineGuid from the system registry. Their lookup failures cannot fall back to a weaker directory ID. Raw system identifiers are only hashed locally. Old records remain available for explicit migration or read-only history; an unknown generation cannot authorize application/recovery. Portable reports exclude this identity and local binding paths.
- Snapshot inventory is bounded by file count, depth, per-file and total bytes. Regular-file inputs are copied without hard links, content is rechecked while copying, and symlinks/outside paths are rejected. Managed environment directories and sensitive profile files are excluded. Required ignored inputs are explicit. JSON evidence reads/writes are capped; older test records are pruned within that bound.
- Validation requires an explicit task allowlist including dependencies. Child processes receive a reduced environment, original trusted profiles are injected through the existing broker rules, and identity credentials are stripped. Secret values and extra argument values/hashes are not persisted. Secret/external/unmanaged contexts are marked as limited evidence before execution and require explicit scope acceptance before application.
- Current and candidate runs use separate temporary roots, Python environments and mutable Flutter copies. Common package caches and global install prefixes are redirected into each snapshot. These directories are not an OS sandbox: commands still have the invoking user's filesystem and network permissions. No deployment or database task is selected by default.
- The task worker waits for a private pipe handshake. Windows attaches it to a kill-on-close Job before allowing it to spawn the command; Unix uses a dedicated process group. Timeout/cancellation terminates the group/job before snapshot cleanup. Forced host/process crashes remain outside orderly cleanup guarantees.
- Application rechecks the latest run and its contents under deterministic project write locks. Transaction journals precede lock writes; recovery verifies all member baselines and ownership before restoring any lock. Restoration covers exact Pinset lock selections, with other state explicitly listed outside its scope.

Local evidence: complete Rust workspace/Clippy and CLI contracts; dirty-to-different-dirty and explicit ignored-input invalidation; separate snapshot writes; timeout and signal cancellation; legacy candidate visibility; mixed-member and idempotent recovery; real Node 24.1.0/24.0.0 Git worktrees with concurrent encrypted profiles; Windows/macOS host identity and process modules cross compiled with strict Clippy. Linux native editor/SDK acceptance and platform-native PR checks are recorded separately when completed.
